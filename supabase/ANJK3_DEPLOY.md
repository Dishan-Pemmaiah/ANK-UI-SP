# ANJK 3 deployment

1. In the existing Supabase project, ensure the `public.is_admin()` helper and `AppUsers` admin role policies from `rls.sql` or `security-hardening-2026-08.sql` are already installed. Do not replace existing Sports tables.
2. Run `migrations/20260914_anjk_hockey_seasons.sql` once if it has not yet been installed. Then run `migrations/20260914_anjk_hockey_match_control_followup.sql`, `migrations/20260914_anjk_hockey_reschedule_history_fix.sql`, `migrations/20260914_anjk_hockey_goal_corrections.sql`, `migrations/20260914_anjk_hockey_match_notes.sql`, and **`migrations/20260914_anjk_hockey_flexible_knockout.sql` last**, in that order. If earlier migrations were already applied, run only those still missing. The knockout migration adds rounds, winner and destination slots, an advancement ledger and guarded RPCs. It marks the existing `anjk-3` season as Knockout; other seasons retain the League default and the existing standings view. Non-tied completed ANJK 3 results receive their score-indicated winner; tied completed fixtures need an admin to confirm their winner and decision method. The migrations preserve legacy Sports tables and hockey records. If a season already has multiple live matches, end or postpone the extras before relying on the one-live-match rule.
3. Optionally run `tests/hockey_standings.sql`, `tests/hockey_match_control.sql`, `tests/hockey_goal_corrections.sql`, and **`tests/hockey_flexible_knockout.sql`** in the SQL editor after all migrations. They check standings, the match lifecycle, scorer corrections, and knockout progression/correction safety. All use transactions that roll back test data; run them with a database owner connection, not from the public app. Review and run the migration and SQL checks manually; this repository does not execute them on your Supabase project.
4. Deploy the React build to Netlify using the existing `REACT_APP_SUPABASE_URL` and `REACT_APP_SUPABASE_ANON_KEY` environment variables. The existing SPA redirect handles `/anjk-3` and `/admin/anjk-3`.
5. Sign in with an existing Admin account. Open `/admin/anjk-3` to enter dates, venue, poster, teams, optional players, fixtures and published/draft announcements. The bundled poster is `public/anjk3/anjk3-poster.jpg`; set its CMS URL to `/anjk3/anjk3-poster.jpg`. The fixture calendar dialog selects the date and start time in IST. In **Knockouts**, add Quarter Final, Semi Final, Final, and 3rd Place as needed; select **Add fixture** within a round to open the existing Fixtures form. Edit or delete fixtures there or from their knockout round. Match Control still handles scoring and winner confirmation; shootouts use a tied match score plus distinct shootout scores. Correct a completed knockout result and winner together. An old active winner/bye placement must be cleared from its unstarted destination before correcting its source result or deleting a linked fixture. A round can be deleted after its fixtures are removed. League/Mixed Group and League standings still update from completed group fixtures.

For a future season, open `/admin/tournaments/<slug>` to create its record, then share `/tournaments/<slug>` as its public page. The ANJK 3 main menu and Home panel continue to point to the ANJK 3 record.

## Official Draw / Ties document

After the flexible-knockout migration above is installed, run **`migrations/20260914_anjk_hockey_draw_documents.sql` once** in the same Supabase project. It creates `hockey_tournament_documents`, publication/version rules, RLS, and a private `anjk-tournament-documents` Storage bucket with a 25 MB limit and the allowed MIME list. Do not make the bucket public. The migration creates Storage policies that permit anonymous signed URLs only for published document objects and admin upload; it does not alter matches or existing Sports tables. Check the bucket remains private with the listed file size/MIME configuration. Optionally run **`tests/hockey_draw_documents.sql`** as database owner; the test rolls back its records and helper override. The SQL test does not replace a live upload/preview check.

Deploy the React build **after** that migration. Keep the existing `REACT_APP_SUPABASE_URL` and `REACT_APP_SUPABASE_ANON_KEY`; no new Netlify variable or route redirect is required. Sign in as an existing Admin, open `/admin/anjk-3` → **Draw / Ties**, upload a file and metadata as a draft, review it, then confirm **Publish**. A new file uses **Upload new revision as draft**, never Edit metadata. The public `/anjk-3?tab=draw` shows the current published revision and collapsed published history; Overview shows a compact card only when a revision is published. Test a PDF/image and a spreadsheet preview on desktop and mobile, and confirm a draft cannot be opened through a public session. Do not execute this migration against Supabase from the repository; apply it manually after review.

### Repair for an already installed early draw migration / missing knockout correction RPC

If `tests/hockey_draw_documents.sql` reported **“Published history was deleted”**, that rollback test exposed an installation missing the published-history delete guard. The failed test transaction did not delete production history. Apply **`migrations/20260914_anjk_hockey_live_repair.sql`** manually after the flexible-knockout and draw-document migrations. It installs that guard and restores `hockey_correct_knockout_result` with the exact argument names the CMS calls; it also reloads PostgREST's schema cache. This is a follow-up migration, not a replacement for either earlier migration. Verify with `select to_regprocedure('public.hockey_correct_knockout_result(uuid,integer,integer,uuid,text,integer,integer)');` (must return a signature), then rerun `tests/hockey_draw_documents.sql` in the SQL editor. Do not rerun a previously applied, non-idempotent migration. If the RPC is still absent, confirm the SQL editor and the site's `REACT_APP_SUPABASE_URL` point to the same Supabase project.

The Knockout Management screen now offers Quarter Final, Semi Final, Final and 3rd Place buttons. Old rounds and fixtures remain visible so organizers can rename or remove them deliberately. Delete a fixture using its confirmed **Delete fixture** action, then delete its empty round; clear a historical linked placement or pending link first if database references block deletion. Bye assignment and automatic progression controls are no longer offered in the simplified screen. Existing match results, notes and goal controls remain in their original tabs.

### Safe knockout fixture deletion

Apply **`migrations/20260915_anjk_hockey_safe_match_delete.sql`** manually after the flexible-knockout migration, then verify `select to_regprocedure('public.hockey_delete_match(uuid)');` returns a signature and deploy the matching React build. The CMS deletion button calls `hockey_delete_match`, which removes active and inactive advancement rows targeting or sourced from the selected fixture, clears unstarted downstream winner slots and pending next-match links, and deletes the fixture with its cascading event history in one transaction. It refuses deletion when a live or completed downstream fixture depends on that match. Optionally run **`tests/hockey_safe_match_delete.sql`** as database owner; it rolls back all test data.

Apply **`migrations/20260915_anjk_hockey_auto_champion.sql`** after the safe-delete migration. A completed Final then sets its winner as champion automatically, a corrected Final replaces the champion, and deleting the Final clears it when no other completed Final remains. **Knockout Management → Champion control** also lets an admin explicitly save or clear the champion. Optionally run **`tests/hockey_auto_champion.sql`** as database owner; it rolls back all test data.
